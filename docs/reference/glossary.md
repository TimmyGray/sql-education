## Domain terms

**Level**
A top-level grouping of curriculum content. Three levels exist: `NOVICE`, `JUNIOR`, `MIDDLE`. Each level is a self-contained progression track with its own set of blocks and XP pool.

**Block**
A curriculum unit within a level. Each block has a theory section (markdown + examples) followed by a set of tasks. Blocks unlock sequentially: block N requires block N−1 to be completed. Completing a block awards XP.

**Task**
An individual SQL problem inside a block. Each task has a prompt, an optional hint, a reference dataset, and a hidden reference query. A student submits their SQL, which is graded against the expected result. A task is either `NOT_STARTED`, `COMPLETED`, or `SKIPPED`.

**Block completion**
A block is completed when every task within it is `COMPLETED` or `SKIPPED` — no tasks remain `NOT_STARTED`.

**XP (experience points)**
Numeric score awarded when a block is completed for the first time. Stored per (user, level) in `UserLevelXp`. Amounts: NOVICE → 100, JUNIOR → 150, MIDDLE → 200 per block.

**Reference query**
The correct SQL solution for a task, written by the curriculum author. It is never sent to the client. It is also deliberately excluded from all AI tutor context. Students can "reveal" a reference answer, which marks the task as `SKIPPED`.

**Expected result**
The baked JSON output of running the reference query against the task's dataset. Stored in `Task.expectedResultJson`. Generated by the seed validator (`pnpm db:validate`) — never entered manually.

**Comparison mode**
How a student's query result is compared to the expected result:
- `ORDERED` — row order must match exactly.
- `UNORDERED` — rows are compared as sets; order doesn't matter.

**Dataset / SandboxDataset**
A named, reusable set of `CREATE TABLE` + `INSERT` statements that define the data a task runs against. One dataset can be shared by multiple tasks. Defined in seed files and stored in the `SandboxDataset` table.

**Sandbox**
The isolated PostgreSQL instance (port 5433) where student SQL queries are executed. It uses a restricted role (`sandbox_runner`) that has no write access to application data. Each execution is isolated: setup SQL runs first, then the student query, then teardown.

**Grading pipeline**
The 3-stage process for evaluating a student's SQL submission:
1. **Forbidden-statement guard** — rejects dangerous SQL keywords.
2. **Sandbox execution** — runs the query on the isolated Postgres.
3. **Result comparison** — compares actual vs expected rows per comparison mode.

**AI tutor**
A per-block question-answering assistant backed by an LLM (via OpenRouter). Limited to 10 questions per (user, block). Instructed to help students think through problems without revealing direct answers.

**AI quota**
The per-(user, block) cap on AI tutor questions (10). Tracked in `UserBlockAiUsage.questionsAsked`. Persisted in the main database.

**Activation code**
A 6-character alphanumeric code emailed to a new user. Must be entered to activate the account (`UserStatus.PENDING → ACTIVE`). Stored in Redis with a 15-minute TTL.

## Technical terms

**Contracts package**
`packages/contracts` (`@sql-edu/contracts`) — a TypeScript package containing all Zod schemas and inferred types shared between the API and the web app. The canonical source of truth for API request/response shapes.

**Monorepo**
This repository manages multiple packages (`apps/api`, `apps/web`, `packages/contracts`, `e2e`) in a single git repo using pnpm workspaces and Turborepo for build orchestration.

**Turbo / Turborepo**
The build system that orchestrates tasks across workspace packages. It respects `^build` dependencies (contracts builds before api/web) and caches task outputs.

**Prisma**
The ORM used by the API. The schema (`apps/api/prisma/schema.prisma`) defines all tables, enums, and relations. Migrations in `apps/api/prisma/migrations/` version schema changes.

**`nestjs-zod`**
NestJS integration for Zod-based validation. The `ZodValidationPipe` (global) automatically validates request bodies against the Zod schema defined in the DTO.

**`sandbox_runner` role**
The restricted PostgreSQL role used to execute student SQL. It has `SELECT` privileges only on the ephemeral tables created by `setupSql`. It cannot access any application tables.
